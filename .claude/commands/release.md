# release.md

릴리즈 노트 작성 가이드

## 작성 단계

1. 현재 브랜치 확인 (`release/x.x.x` 형식)
2. 이전 릴리즈 태그 이후 변경사항 수집:
   ```bash
   git log --oneline <이전_태그>..HEAD
   git log --oneline <이전_브랜치>..HEAD
   ```
3. 관련 PR 및 이슈 확인
4. 기존 릴리즈 노트 형식 참조: `docs/releases/` 폴더

## 릴리즈 노트 형식

```markdown
# 🚀 v{버전} Latest

**릴리즈 날짜:** YYYY-MM-DD

---

## ✨ 새로운 기능

### 기능명 (#이슈번호)
기능 설명

- 세부 사항 1
- 세부 사항 2

---

## 🔧 개선 사항

### 보안 강화 (해당 시)
| 항목 | 설명 |
|------|------|
| 항목1 | 설명1 |

### 기타 개선
- 개선 사항 목록

---

## 🐛 버그 수정

- 버그 수정 내용 (#이슈번호)

---

## 📚 문서화

- 문서 변경 내용

---

## 🔗 관련 이슈 & PR

| PR | 제목 | 이슈 |
|----|------|------|
| #번호 | PR 제목 | #이슈번호 |

---

## 🏗 기술 변경 (해당 시)

| 변경 | 이전 | 이후 |
|------|------|------|
| 항목 | 이전값 | 이후값 |

---

## 업그레이드 가이드

이번 릴리즈는 하위 호환성을 유지합니다. (또는 마이그레이션 필요 시 가이드 제공)

\`\`\`bash
git pull origin main
pnpm install
pnpm build
\`\`\`
```

## 참고사항

- 파일 위치: `docs/releases/v{버전}.md`
- 커밋 타입별 분류:
  - `feat` → ✨ 새로운 기능
  - `fix` → 🐛 버그 수정
  - `refactor` → 🔧 개선 사항
  - `docs` → 📚 문서화
  - `security`, `chore(security)` → 보안 강화
- 변경사항이 적은 패치 버전은 간소화 가능
